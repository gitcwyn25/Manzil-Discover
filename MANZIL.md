# Manzil Discover

This is an independently hosted fork of TREK v5.1.0, retaining its complete
feature implementation and AGPL-3.0 license. The source base is commit
`dc36c21c08f681fd2806764fad8e17b270f6f175`.

## Current changes

- Manzil logos, app icons, loading marks, HTML titles and installable-app name.
- Product text changes through an AST-based build transformation. Internal
  identifiers, service-provider names/URLs and legal attribution remain.
- Public registration follows the backend's existing registration policy.
  Completing the administrator's own password change remains mandatory for
  that account; it does not hide ordinary-user signup when signup is enabled.
- Shareable signup URL: `/login?mode=register`.
- `/source.html` links to the fork, upstream source, license and notices.

Build with `docker build -f Dockerfile.manzil .`. All application source must
be present. The pinned public-file manifest also allows the build to seed
unchanged large public assets from the pinned upstream runtime.
The build applies branding before compiling the frontend/shared/backend, then
keeps the upstream runtime's document tools and supporting data assets.

To publish branding independently of backend integration, build the client,
then run `node manzil-branding/package-branding.mjs`. This release overlays the
branded client onto the pinned upstream backend, preserves bundled assets and
the persistent volume, and records client hashes and source commit in
`release.json`. Set Railway's `RAILWAY_DOCKERFILE_PATH=Dockerfile` for this
release. The full backend build continues to use `Dockerfile.manzil`.

For a runtime package, run the workspace type checks and build shared, server
and client first, commit the reviewed source, then run
`node manzil-branding/package-runtime.mjs`. This records the source commit and
SHA-256 hashes of all three build outputs. Deploy that immutable release
directory with `RAILWAY_DOCKERFILE_PATH=Dockerfile`; native dependencies and
supporting data still come from the pinned upstream image.

Focused local tests:

```sh
node --test manzil-branding/brand-source.test.mjs client/src/pages/login/registrationPolicy.test.mjs
```

The build transformation is idempotent. Installed-app icons and service-worker
precache assets are regenerated by the normal upstream frontend build.

## Supabase integration scope

Target project: `wfabehnihelxemztmvca` (confirmed by the owner).

Supabase authentication and S3-compatible private storage are the intended
integration paths. This release of TREK uses a persistent SQLite application
database; its experimental PostgreSQL probe is not a production migration and
must never be run against this Supabase project.

Set `SUPABASE_URL` and `SUPABASE_PUBLISHABLE_KEY` to enable public accounts.
The server verifies the provider identity before issuing its own HttpOnly
session, keeps local roles and MFA, requires confirmed email, and refuses
automatic email-based linking to an existing account. Provider metadata never
grants administrator access. Native account creation is disabled in this mode;
existing local users sign in at `/login?auth=local`.

Confirmation returns to `/login?auth_callback=1`; recovery returns to
`/reset-password?auth=supabase`. Add the Discover origin to Supabase redirect
URLs and configure custom SMTP. The owner confirmed both settings. Actual
inbox delivery still needs a user to complete an email round trip.

Private uploads use the native S3 driver and the private `manzil-discover`
bucket. The owner chose to keep its 4 MB limit. Set `SUPABASE_S3_REGION` (Singapore: `ap-southeast-1`),
`SUPABASE_S3_ACCESS_KEY_ID`, `SUPABASE_S3_SECRET_ACCESS_KEY` and
`SUPABASE_S3_BUCKET` in Railway only. The driver handles repeated edge headers
and Supabase path-style requests. No storage credentials are sent to browsers.

For a one-time rollout set `MANZIL_PROVISION_SUPABASE_STORAGE=1`. After local
health is ready, the detached job probes the destination and preflights user
uploads against 4 MB. It uses existing copy-before-flip migration, preserves
source files and custom routes, and leaves oversized categories local. Caches
and backups stay on the persistent volume. Storage errors do not block startup.
Remove the rollout flag after verification. The same `/persist` volume, numeric
users, trip database and authorization model remain. After any storage route
has moved, use the patched S3-compatible runtime for rollback; the original
upstream driver does not handle this Supabase endpoint correctly.
